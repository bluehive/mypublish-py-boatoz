実データは非公式のBoatrace Open API results/v3から日次JSONを取得します。取得可能な日付は提供元の公開状況に依存します。未公開日と開催なしを同じ意味に扱わないでください。
```bash
boatoz download --start 2026-01-01 --end 2026-01-03
boatoz parse data/raw/*.json --output data/parsed_races.csv
```
既存ファイルは再取得せず、404はunavailableとして報告します。その他の通信エラーは処理を中断します。データ保存先は--dest、既定のデータルートはBOATRACE_DATA_ROOTで指定できます。PowerShellではファイルの一覧を引数に展開するなど、シェルに応じてパスを渡してください。

通信なしで試す場合は次を実行します。
```bash
boatoz parse tests/fixtures/results.json --output output/fixture.csv
```
JSONはレースの中に艇の配列が入った構造です。正規化では1行を1艇の出走に揃え、日付・会場・レース番号からrace_idを作ります。CSVの1行は1レースではありません。

失格等で1〜6以外の着順は欠損になります。欠損を6着や0着へ置き換えると平均が変わるので避けます。同一レース・同一艇の重複は例外にします。結果データには事前のモーター成績がないため、取得できない項目を推測して埋めません。

練習：fixture.csvの行数を確認してください。1レース6艇なので6行です。期間の長さとレース件数は別々に記録しましょう。


## 実践：常滑公式ページを時刻付きで観測する

過去の結果JSON収集に加え、出走表・直前情報・3連単オッズを20秒周期で取得する実装を追加しています。
投票締切の2分前で停止し、応答ごとの取得時刻と元HTMLを保存します。
`boatoz tokoname plan`は通信せずに停止計画を表示し、`collect`が実際の取得を行います。
`summary`はpandasでオッズ推移を集計し、`export`は3種類の観測をCSV化します。

締切は発走時刻と異なります。公式表示の確認とタイムゾーンの指定が必要です。
サイトの更新頻度と取得周期も異なるため、同じHTMLを再観測しただけで新しい値になったとは言えません。
詳しい対象項目・停止条件・実行例はリポジトリの`docs/tokoname-collection.md`を参照してください。
